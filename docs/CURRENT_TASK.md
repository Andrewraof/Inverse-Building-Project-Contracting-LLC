# CURRENT_TASK — مراجعة وتقوية عملية Meta OAuth ومزامنة Page Access Tokens

الحالة: قيد المراجعة — بانتظار نجاح اختبارات Odoo الفعلية قبل الاعتماد

## المشكلة

- عند إعادة OAuth كانت تظهر رسالة:
  `This Meta Page is already configured for this company`.
- تم تنفيذ upsert، لكن نحتاج مراجعة شاملة للتأكد أن العملية
  لا تتوقف بسبب صفحة مكررة.
- يجب عدم السماح باعتبار `meta_page_id` كأنه `page_access_token`.
- عند إعادة الربط يجب تحديث Page Access Token تلقائيًا.
- الصفحات المؤرشفة يجب إعادة تفعيلها وتحديثها.
- فشل صفحة واحدة يجب ألا يمنع مزامنة باقي الصفحات.
- رسائل الخطأ الحالية يجب أن تكون واضحة ولا تعرض التوكن.
- يجب التأكد أن Disconnect يمسح التوكنات بطريقة صحيحة، وأن
  OAuth الجديد يعيد إنشاءها.

## المطلوب

1. مراجعة OAuth callback ومزامنة الصفحات.
2. إصلاح أي مسار يسمح بحفظ Page ID داخل Page Access Token.
3. إضافة validation يرفض التوكن الفارغ أو التوكن المساوي لـ Page ID.
4. جعل المزامنة upsert وآمنة للصفحات النشطة والمؤرشفة.
5. معالجة كل صفحة داخل savepoint مستقل حتى لا توقف صفحة واحدة
   باقي الصفحات.
6. تحديث اختبارات الوحدة لتغطية:
   - صفحة جديدة.
   - صفحة موجودة.
   - صفحة مؤرشفة.
   - توكن غير صالح.
   - أكثر من صفحة وإحداها تفشل.
   - Disconnect ثم Reconnect.
7. لا نشر على السيرفر ولا تعديل قاعدة البيانات.
8. تسليم Git diff كاملًا وأوامر الاختبار والمخاطر.

## نطاق العمل

- `models/meta_page.py` — `_upsert_from_meta` + حقل `page_access_token`.
- `models/meta_account.py` — `action_disconnect` + `_request`.
- `controllers/main.py` — `oauth_callback` (حلقة مزامنة الصفحات).
- `tests/test_meta_connector.py` — تحديث/إضافة اختبارات.

## شروط التنفيذ

- أقل تعديلات ممكنة؛ لا حذف أو تغيير لوظائف قائمة بدون ضرورة.
- لا Tokens أو App Secrets أو كلمات مرور في الكود.
- توافق Odoo 19 Community.
- لا نشر على السيرفر ولا تعديل مباشر على قاعدة البيانات.
